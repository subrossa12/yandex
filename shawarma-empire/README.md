# Шаурма Империя: симулятор бизнеса

Идл-игра (incremental) для каталога Яндекс Игр. Чистый HTML + CSS + JavaScript:
без сборщиков, npm, фреймворков и внешних запросов. Папка `game/` открывается
двойным кликом по `index.html` и работает.

Сеттинг: игрок начинает с ларька шаурмы и разрастается до сети общепита —
Ларёк → Кафе → Пекарня → Пиццерия → Суши-бар → Бургерная → Ресторан →
Фудкорт → Сеть по стране.

---

## Язык

Три языка: **RU, TR, EN**. Турецкий — рекомендация платформы, это её второй
рынок после России.

Русский — **язык по умолчанию всегда**, включая запуск без SDK. Другой
включается в двух случаях: платформа явно сообщила его
(`ysdk.environment.i18n.lang`) или игрок сам выбрал язык в настройках. Язык
браузера намеренно не спрашивается — иначе на машине с английской локалью
игра открывалась бы англоязычной.

## Запуск и сборка

```sh
# локально: просто открыть game/index.html в браузере
# (SDK нет — обёртка уходит в режим localStorage, реклама даёт награду сразу)

node tools/simulate.js 120       # кривая дохода за 2 часа игры
node tools/simulate.js 360       # длинная дистанция, циклы престижа
node tools/simulate.js 120 --csv # в csv, если хочется график

# прикинуть баланс под будущий флаг, не трогая билд:
node tools/simulate.js 120 --flag prestige.factor=180

node tools/smoke.js              # прогон в Chromium: консоль, вёрстка, механики
node tools/smoke.js --shots      # плюс скриншоты в docs/shots/

sh tools/build.sh                # проверка требований + build/shawarma-empire.zip
```

`build.sh` перед упаковкой проверяет технические требования платформы —
index.html в корне, латиница в именах файлов, вес распакованного билда,
отсутствие внешних запросов, подключённый SDK и вызов `LoadingAPI.ready()`.
Если что-то нарушено, архив не собирается.

## Вёрстка: два решения, которые нельзя ломать

Оба продиктованы требованиями платформы, и оба легко сломать безобидной
правкой CSS. Если трогаешь `css/main.css`, прогони после этого
`node tools/smoke.js` — он проверяет ровно эти два пункта.

**1. Геометрия поля на десктопе** (п. 1.6.2.1 и 1.6.2.2). Поле обязано
дотягиваться до края доступной области хотя бы по одной оси и при этом
не быть длиннее короткой стороны более чем вдвое:

```css
width:  min(100vw, max(420px, 52vh));   /* 52vh вместо 50vh — запас на округление */
height: min(100vh, 192vw);              /* узкое окно: упираемся в края по горизонтали */
```

Отношение выходит 1.92 на любом размере окна. Если поставить фиксированную
высоту вроде `min(100vh, 940px)`, на высоком мониторе сверху и снизу
появятся поля — это нарушение 1.6.2.1.

**2. Главный экран без прокрутки** (п. 1.10.4). Все девять точек должны
помещаться на экран целиком. Держится на трёх вещах:

- ещё не открытые точки не рендерятся вовсе (`hidden`), а не показываются
  замками — в начале игры на экране две карточки;
- карточки делят высоту между собой (`flex: 1 1 0` с `min-height`/`max-height`),
  кнопки стоят сбоку, а не под полосой прогресса;
- плотность падает с высотой экрана: медиазапросы на 820 и 680 px ужимают
  карточки, шапку и таббар. На 320×568 карточка ужимается до 44 px — и всё
  ещё влезает.

Свободное место под карточками занимает блок «Дальше откроются»: он же
решает п. 1.15 — экран не выглядит наполовину пустым, пока открыто мало
точек.

## Конфигурация: локальные дефолты + флаги

Баланс идла крутится неделями по метрикам. Если каждое число зашито в билд,
любая правка — это новая сборка и новая модерация. Поэтому все настраиваемые
числа идут через `game/config.js`:

```
data/balance.js  →  дефолты, зашитые в билд, работают всегда
       ↓ перекрываются
ysdk.getFlags()  →  один запрос на старте, значения из Консоли
       ↓
эффективный баланс → его и видит вся игра (SE.BALANCE, Config.getFlag)
```

Сейчас через слой проходит **111 ключей**: цены и доходность всех девяти
точек, `costGrowth`, цены менеджеров, пороги ускорения, все апгрейды,
формула престижа целиком, кап офлайн-дохода, награды и кулдауны пяти
рекламных офферов, правила межстраничной рекламы, номер счётчика Метрики.

Четыре вещи, на которых этот слой держится, и ломать их нельзя:

1. **Игра работает без сети.** Дефолты зашиты в билд, и это не запасной
   путь, а нормальный режим: у игрока может не быть интернета в метро.
2. **Запрос один и только на старте.** Баланс не должен меняться под
   игроком посреди сессии.
3. **Таймаут.** Запрос флагов гонится наперегонки с таймером на 3 секунды.
   Зависший промис не имеет права задерживать загрузку игры — в `smoke.js`
   есть тест ровно на этот случай.
4. **Мусор отбрасывается поштучно.** Каждое значение парсится по типу и
   проходит санитарную проверку (`costGrowth` не может быть отрицательным,
   делитель — нулём). Один плохой флаг не роняет весь конфиг.

Проверить будущий флаг локально, ничего не пересобирая:

```sh
node tools/simulate.js 120 --flag prestige.factor=180
```

## Аналитика

Счётчик Метрики **не подключается кодом**. Раньше подключался, и из-за
этого архив с игрой начинали отмечать антивирусы: создание тега скрипта
плюс чужой домен плюс вставка в документ — их типовая сигнатура подмены
скрипта. Срабатывание ложное, но проверять архив будут все, а объяснять
каждому невозможно.

Поэтому в билде нет ни одного внешнего адреса, и сборка это проверяет
без исключений. Чтобы включить аналитику, когда номер счётчика уже есть:

1. вставить в `game/index.html` перед закрывающим `</body>` штатный
   сниппет счётчика из интерфейса Метрики (тот самый, что даётся для
   любого сайта);
2. вписать номер в `metrica.counterId` — в `data/balance.js` или флагом.

`core/metrica.js` сам ничего не грузит: он пользуется тем, что уже лежит
на странице. Если тега нет, а номер задан — модуль скажет об этом в
консоли, чтобы не ждать месяц пустых отчётов.

Цели снимаются в любом случае, даже когда счётчик выключен, — их видно в
`SE.Metrica.journal()`. На этом же журнале построен автотест: он
проверяет, что события вообще шлются, не поднимая настоящий счётчик.

Список целей и что по ним видно — в `docs/moderation.md`. Две самые
полезные: разрыв между `rv_shown_*` и `rv_rewarded_*` показывает, где
оффер не дожимается, а `wall_hit` — где именно игрок упирается и уходит.

## Баланс

Все числа — в `game/data/balance.js`. После правки прогоняй `simulate.js` и
смотри на две вещи: когда открывается первый престиж и как ведут себя циклы.

Текущая калибровка (оптимальный игрок, симуляция):

| Момент | Факт |
|---|---|
| Первый доход | сразу, тап приносит деньги каждую секунду |
| Первый менеджер | ~1 мин у идеального игрока, 3–5 мин у живого |
| Все 9 точек открыты | ~40 мин |
| Первый престиж | 41 мин |
| Циклы престижа дальше | 31 → 25 → 21 → 17 мин, каждый быстрее |

Живой игрок медленнее симуляции примерно в полтора раза — первый престиж
попадает в 45–60 минут, как и задумано.

Ключевые ручки:

- `businesses[].baseCost / costGrowth` — темп открытия точек
- `businesses[].managerCost` — где возникает «затык» и мотивация к рекламе
- `prestige.minStars` — длина забега (больше = длиннее)
- `prestige.bonusPerStar` и `prestige.starExponent` — сила звёзд.
  Показатель < 1 намеренно гасит разгон: при линейном бонусе забеги
  на длинной дистанции схлопываются с 25 минут до пяти.

## Интеграция SDK

Все вызовы — в `game/platform/platform.js`, сверены с документацией SDK.
Каждый защищён feature-detection и try/catch: если метод недоступен, игра
не падает, а работает без этой функции.

| Что | Вызов |
|---|---|
| Подключение | `<script src="/sdk.js">` — относительный путь, как требуется для игр, загружаемых архивом |
| Инициализация | `YaGames.init()` |
| Готовность | `ysdk.features.LoadingAPI.ready()` |
| Геймплей | `ysdk.features.GameplayAPI.start() / .stop()` |
| Пауза от платформы | `ysdk.on('game_api_pause' \| 'game_api_resume', cb)` |
| Смена аккаунта | `ysdk.on(ysdk.EVENTS.ACCOUNT_SELECTION_DIALOG_CLOSED, cb)` |
| Игрок | `ysdk.getPlayer()`, `player.isAuthorized()`, `player.setData(obj, true)`, `player.getData([key])` |
| Авторизация | `ysdk.auth.openAuthDialog()` |
| Хранилище | `ysdk.getStorage()` — устойчивый аналог localStorage |
| Флаги | `ysdk.getFlags({ defaultFlags })` — один раз на старте, с таймаутом |
| Статистика | `player.setStats()` / `getStats()` — числовая витрина игрока |
| Ярлык | `ysdk.shortcut.canShowPrompt()` / `showPrompt()` — с третьей сессии |
| Баннер | `ysdk.adv.showBannerAdv()` / `hideBannerAdv()` — заложено, по умолчанию выключено |
| Rewarded | `ysdk.adv.showRewardedVideo({ callbacks: { onOpen, onRewarded, onClose, onError } })` |
| Interstitial | `ysdk.adv.showFullscreenAdv({ callbacks: { onOpen, onClose(wasShown), onError } })` |
| Покупки | `ysdk.getPayments()`, `getCatalog()`, `purchase({ id })`, `getPurchases()`, `consumePurchase(token)` |
| Лидерборд | `ysdk.leaderboards.setScore(name, score)`, `getEntries(name, { quantityTop, includeUser, quantityAround })` |
| Проверка метода | `ysdk.isAvailableMethod('leaderboards.setScore')` |
| Оценка | `ysdk.feedback.canReview()`, `requestReview()` |
| Язык | `ysdk.environment.i18n.lang` |
| Время | `ysdk.serverTime()` |

Четыре места, где легко ошибиться, и как здесь сделано:

1. **События паузы — строки**, а не значения из `ysdk.EVENTS` (там только
   `EXIT`, `HISTORY_BACK` и диалог выбора аккаунта). Без подписки на
   `game_api_pause` игра не узнает о полноэкранной рекламе, которую
   платформа показывает на старте сама, — у неё нет колбэков.
2. **Постоянные покупки не консумируются.** `consumePurchase()` удаляет
   покупку безвозвратно; отключение рекламы и множитель навсегда должны
   оставаться в `getPurchases()` — оттуда они и восстанавливаются на
   другом устройстве. Гасится только расходуемый стартовый набор.
   Флаг — `permanent` в `data/shop.js`.
3. **`player.getMode()` устарел** — авторизация проверяется через
   `player.isAuthorized()`.
4. **Лидерборд — `ysdk.leaderboards`**, инициализация через
   `ysdk.getLeaderboards()` устарела. Запись результата доступна только
   авторизованным, поэтому перед ней спрашиваем `isAvailableMethod()`.

### Как проверить подключение

Открой игру с debug-панелью (в Консоли кнопка **Открыть с debug-панелью**
или параметр `debug-mode=16` в адресе) и посмотри индикатор лоадера в левом
нижнем углу: `IT` — SDK подключён верно, `IF` — используется старый лоадер.

Ещё две вещи, которые нужно завести в Консоли:

1. **Товары** с id `noads`, `x2forever`, `offline8h`, `starterpack`
   (или поменяй id в `game/data/shop.js`). Пока каталог из SDK не пришёл,
   вкладка «Магазин» скрыта — это штатное поведение.
2. **Лидерборд** с техническим именем `total` (суммарная выручка за все
   престижи). Если его нет, вызовы просто молча игнорируются.
3. **Счётчик Метрики** и цели из `docs/moderation.md`. Номер вписывается в
   `metrica.counterId` или задаётся флагом.
4. **Флаги** — только те ключи, которые собираетесь крутить. Заводить все
   111 сразу не нужно: незаданные берутся из билда.

Sticky-баннер включается в Консоли, а не в коде. Сверху и снизу оставлен
воздух, критичных кнопок вплотную к краям нет.

## Что игра осознанно НЕ делает

- не ходит ни на один внешний домен, не грузит шрифты и CDN;
- не содержит интерактивного ИИ (прямой запрет п. 1.23);
- не имитирует рекламные блоки своими кнопками (п. 1.16);
- не вызывает полноэкранную рекламу по таймеру — только в двух логических
  паузах: после престижа и при открытии новой точки;
- не выдаёт награду за rewarded в `onClose` — только в `onRewarded`.
